# Unreachable In-Use Database Guard in Monthly Retention Cleanup

## Bug Summary
`SQLiteDriver.cleanup_old_databases()` guards against deleting the actively
used database file (`_current_db_path`), but the guard can never engage:
`cleanup_old_databases()` is called only from `connect()` (before any
connection exists, so `_current_db_path` is `None`) and from
`_switch_db_if_needed()` (after `self.close()` has already reset
`_current_db_path` to `None`). The protection is therefore dead code, and the
data-loss window it was written to close remains open.

## Severity & Impact
- **Severity**: Medium (Silent Data Loss)
- **Impact**: With `retention_months` disabled (`retention_months: 0`), a
  server restart deletes *every* monthly database file, including the current
  month's file containing all of that month's logs. At a month switch, the
  newly targeted database file can likewise be deleted before it is reopened.

## Affected Components
- File: [db/sqlite.py](../../aiosyslogd/db/sqlite.py)
- Function: `cleanup_old_databases()`, `connect()`, `_switch_db_if_needed()`

## Root Cause Analysis
The guard reads the protected path from instance state
(`self._current_db_path`), yet both call sites run cleanup at a point where
that state is deliberately cleared:

1. `connect()`: runs at driver initialization, before the first write has
   opened any connection.
2. `_switch_db_if_needed()`: closes the old connection *before* cleanup, and
   `close()` sets `_current_db_path = None`.

```python
# _switch_db_if_needed() — close() wipes the state the guard needs
if self.db:
    await self.close()          # sets _current_db_path = None
...
await self.cleanup_old_databases()   # guard sees None, never protects
```

Additionally, the guard compared raw strings while `_get_database_files()`
uses `glob`, which can return paths in a different form than the template
(e.g. a leading `./`), so a working guard could still have failed to match.

## Reproduction Scenario
1. Set `retention_months: 0` in `aiosyslogd.toml`.
2. Let the server run during a month, then restart it.
3. On startup, `connect()` → `cleanup_old_databases()` treats
   `retention_months <= 0` as "delete all files" and removes the current
   month's database file.
4. The file is silently recreated empty on the next write; the month's logs
   are lost.

## Remediation Implemented
Replace the state-dependent guard with an explicit `protect` parameter that
the caller supplies:

- `cleanup_old_databases(protect: set[str] | None = None)` filters protected
  paths out of the deletion list, comparing both sides with
  `os.path.abspath()` so `glob` results always match template-derived paths.
- `connect()` protects `self._get_db_path_for_month(datetime.now())`, i.e.
  the file the driver is about to use for the current month.
- `_switch_db_if_needed()` protects `target_db_path`, the file about to be
  reconnected after the switch.

Regression tests were added in `test_sqlite_cleanup.py`:
`test_connect_never_deletes_current_month_file` and
`test_cleanup_protects_given_paths`.

## Validation
- The new regression tests reproduce the loss scenario on the old code and
  pass with the fix.
- The full suite passes (150 tests), along with ruff, black, and mypy.
