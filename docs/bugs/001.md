# CSRF Protection Bypass via Content-Type Filtering

## Bug Summary
The application's `@app.before_request` hook `csrf_protect` attempts to enforce CSRF validation on mutating HTTP methods (`POST`, `PUT`, `DELETE`). However, it contains a conditional check that only performs validation if `application/x-www-form-urlencoded` is present in `request.content_type`. When a request is submitted with `multipart/form-data`, `text/plain`, or `application/json`, CSRF validation is completely bypassed.

## Severity & Impact
- **Severity**: High (Security Vulnerability)
- **Impact**: An attacker hosting a malicious webpage can execute Cross-Site Request Forgery (CSRF) attacks against authenticated users. For example, submitting an admin form using `<form enctype="multipart/form-data">` allows adding new admin users, deleting existing users, or changing user passwords without possessing a valid CSRF token.

## Affected Components
- File: [web.py](../../aiosyslogd/web.py#L110-L124)
- Function: `csrf_protect()`

```python
if request.method in ["POST", "PUT", "DELETE"]:
    # For form requests, check form data
    if (
        request.content_type
        and "application/x-www-form-urlencoded" in request.content_type
    ):
        form_data = await request.form
        token = session.get("_csrf_token")
        ...
        if form_data.get("csrf_token") != token:
            abort(403)
```

## Root Cause Analysis
1. The `Content-Type` check assumes web browsers only submit forms as `application/x-www-form-urlencoded`.
2. Standard HTML forms can specify `enctype="multipart/form-data"`. When received, `request.content_type` contains `multipart/form-data; boundary=...`, causing the substring check `"application/x-www-form-urlencoded" in request.content_type` to evaluate to `False`.
3. The hook returns immediately without checking the token, and the route proceeds to process the form data via `await request.form`.

## Steps to Reproduce
1. Log in as an administrator to `http://localhost:5141`.
2. In another browser tab (or external site), submit a cross-origin POST request using standard HTML:
   ```html
   <form action="http://localhost:5141/users/delete/victim_user" method="POST" enctype="multipart/form-data">
       <input type="submit" value="Click Here">
   </form>
   ```
3. Submit the form without supplying a `csrf_token`.
4. Observe that the user `victim_user` is successfully deleted instead of receiving an HTTP 403 Forbidden response.

## Proposed Remediation
Remove the `Content-Type` filter restriction so all state-changing form requests are subject to CSRF validation:

```python
if request.method in ["POST", "PUT", "DELETE"]:
    token = session.get("_csrf_token")
    if not token:
        session["_csrf_token"] = os.urandom(24).hex()
        token = session["_csrf_token"]

    form_data = await request.form
    if form_data.get("csrf_token") != token:
        abort(403)
```
