# Bootstrap Modal Multiple Instantiation and Memory Leaks

## Bug Summary
In `index.html`, every interaction that triggers a modal (e.g. clicking `#gemini-btn`, `showGeminiAuthModal()`, or submitting auth) creates a new instance using `new bootstrap.Modal(document.getElementById(...))` rather than retrieving or creating an existing instance via `bootstrap.Modal.getOrCreateInstance()`.

## Severity & Impact
- **Severity**: Low (UI Glitches & Memory Leak)
- **Impact**: Successive clicks create multiple Bootstrap Modal instances bound to the same DOM element. This can cause backdrop overlays to remain permanently on the screen after dismissal, and `bootstrap.Modal.getInstance(...)` can target an orphaned instance, failing to hide the modal.

## Affected Components
- File: [index.html](../../aiosyslogd/templates/index.html#L328-L334), [index.html](../../aiosyslogd/templates/index.html#L404-L407), [index.html](../../aiosyslogd/templates/index.html#L496-L499)

```javascript
// Example from index.html:
function showGeminiAuthModal() {
    const modal = new bootstrap.Modal(document.getElementById('geminiAuthModal'));
    modal.show();
}
```

## Root Cause Analysis
Calling `new bootstrap.Modal(el)` initializes a new internal Bootstrap controller on the element every time without checking if an active instance already exists.

## Steps to Reproduce
1. Open the Log Viewer.
2. Click the Gemini (`✦`) button without an API key configured to show the auth modal.
3. Close the modal, then click the Gemini button again.
4. Inspect the DOM to observe multiple backdrop elements or unresponsive dismissal events.

## Proposed Remediation
Use `bootstrap.Modal.getOrCreateInstance()` throughout the JavaScript code:

```javascript
function showGeminiAuthModal() {
    const el = document.getElementById('geminiAuthModal');
    const modal = bootstrap.Modal.getOrCreateInstance(el);
    modal.show();
}
```
