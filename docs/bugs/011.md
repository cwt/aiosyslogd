# CSRF Token Leakage in Search and Filter GET Forms

## Bug Summary
In both `index.html` and `activity.html`, search and filter forms are defined with `method="get"`, but include `<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">`.

```html
<!-- From index.html and activity.html -->
<form action="{{ url_for('index') }}" method="get" class="bg-white p-4 rounded-lg shadow-sm mb-4">
    <input type="hidden" name="csrf_token" value="{{ csrf_token() }}">
    ...
```

## Severity & Impact
- **Severity**: Low (Information Leakage / Security Smells)
- **Impact**: When the user searches, filters, or changes the selected database via dropdown, the CSRF token is submitted as a URL query parameter (`/?csrf_token=9e8f...&q=error`). This leaks the CSRF token into web server access logs, browser history, bookmarks, and `Referer` headers. Furthermore, the token persists in generated pagination links.

## Affected Components
- File: [index.html](../../aiosyslogd/templates/index.html#L25-L27)
- File: [activity.html](../../aiosyslogd/templates/activity.html#L11-L13)

## Root Cause Analysis
GET requests are idempotent read operations that do not modify server state and do not require CSRF protection. Placing a hidden CSRF token input in a GET form causes the browser to append it to the query string upon form submission.

## Steps to Reproduce
1. Navigate to `http://localhost:5141/`.
2. Change the database dropdown or submit a search.
3. Observe the browser URL bar: `http://localhost:5141/?csrf_token=...&db_file=...`.

## Proposed Remediation
Remove the `<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">` element from all GET forms in `index.html` and `activity.html`.
